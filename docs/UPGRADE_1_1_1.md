# 1.1.0升级到1.1.1

本补丁针对赛事评价未触发预先联网，以及短回复整理失败后让用户重复提问。没有取得这轮云端原始模型回答，不能将旧故障断定为DSH丢失工具结果。本补丁修复可复现的路径，并记录下一次现场定位需要的阶段信息。

## 部署

1. 下载v1.1.1发布页的ZIP与SHA256.txt，先校验文件摘要和ZIP内MANIFEST.sha256。解压到新的临时目录，禁止把包内文件替换成聊天导出包或旧安装包。
2. 确认实际菲比实例、Hub插件目录、配置和数据位置。备份线上插件代码、配置，并通过Hub在线备份保存生产数据库。生产库已经schema2时不重新迁移、不补分、不用导出库替换；记录升级前全部成员的现有分数及120/fixed_score=120，以当前在线库为准。
3. 在菲比管理页停用Hub，在原插件位置安装1.1.1源码或导入新版包；保留原数据与配置。对旧线上额外代码改动先保存差异，安装包中的main.py、hub/dialogue.py、hub/output.py需与清单一致，不能再混入旧版本的分流实现。只重载该插件；若框架要求重启，仅重启实际菲比实例。
4. 保持现有engine=dsh、模型、工具白名单、自动记忆设置和网络。Bridge健康接口仍为tool_protocol:2即可，本次不需要重建Bridge，不替换.env/secrets/网络/hub_state，不操作奶龙或其他插件。
5. 查看“菲比系统状态”为Hub1.1.1，核对当前生产库完整性和分数。保留升级后的库；回滚只恢复本次备份的插件源码与配置，不用旧数据库覆盖新消息。

## 指定群复测

沿用用户指定的“菲比的被窝群”，先核对实际群ID，不自行推断群名别名或向其他群发消息。优先由用户发送；如需要部署助手代发，先取得该次代发授权。

- “菲比你怎么看VCTcn2-16”：日志required=True，真实搜索成功；回答应回应赛区表现，核对赛事年份和数字，正文1～2句、最多100字，最多一个实际来源。
- 接着“你怎么看？”：延续当前成员的有效赛事话题；换成员、换群、过期话题仍遵守原隔离规则。
- “你觉得我怎么样”：不会仅因评价措辞强制联网。“不用查，你怎么看VCTcn2-16”：不执行任何联网工具。
- 同轮日志应标明configured=dsh、actual=dsh；如actual=native_fallback，需如实报告Bridge回退原因，不能算DSH验收通过。
- 原长回答不合规但整理成功时outcome=rewritten；纯换行合并为compacted；原回复合规为original；失败为fallback，reason可区分rewrite_timeout、rewrite_error_异常类型、rewrite_too_long、rewrite_too_many_sentences、empty等。
- 压缩失败且查询成功时应回复“资料查到了，但这次回答整理失败了。”并保留来源；这只证明失败反馈准确，不能算正常答复验收通过。不要在生产上故意中断真实用户请求测试超时，故障注入已由本地回归覆盖。
- 用户本人仍120/fixed_score=120，普通成员现有分数保持；同群公共上下文能跨成员接话，个人偏好与情绪独立。

日志仅记录请求摘要、引擎、工具名/状态、字符数和整理结果，不写完整私聊、资料、密钥或异常原文。turn字段为消息ID的SHA256前12位，可与Hub轮次记录关联。若仍失败，收集该轮phase日志、最终回复及用户授权导出的模型原文后继续定位，不再只按搜索词表推断根因。

部署端最终交回：安装版本与清单校验、数据库完整性及分数核对、Bridge协议、群内原问题/最终回复/实际来源、同轮日志、实际引擎。安装成功和模拟测试不等于真实模型及QQ群实收验收通过。
